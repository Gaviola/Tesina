# RFC 04 — Carga de datasets, splits e image store unificados

**Fecha:** 2026-05-25
**Estado:** Propuesta arquitectónica
**Alcance:** `Codigo/src/data/`

## Problema

`src/data/` tiene 4 datasets (HAM10000, HIBA, SkinCaRe, MM-Skin) que repiten la misma lógica:

- Cargar el JSON de splits y filtrar por `split` ∈ {train, val, test} → ≈3 líneas idénticas en cada `__init__`.
- Resolver paths de imagen contra múltiples directorios candidatos.
- Manejo de errores transitorios de NFS dentro de `_open_image()` (vive en `BaseDataset` pero no es unit-testable: requiere fallar NFS real).
- Cálculo de `class_weights` hardcodeado sobre `sample["label"]`.

Friction adicional:

- No hay versionado declarado de splits: si pasamos de `splits_v1.json` a `splits_v2.json`, las 4 clases hay que tocarlas.
- El metadata (fototipo en HIBA, age/sex en HAM10000, caption en SkinCaRe) tiene esquemas heterogéneos pero el `dict` retornado pretende ser uniforme — los downstream consumers asumen keys que no siempre existen.
- Tests: no hay. Cualquier corruption en el JSON o disk error sólo se descubre cuando un job de 6 hs en Mendieta falla en la mitad.

## Interfaz propuesta

Diseño "minimal" como punto de entrada, con dos helpers reusables internos (`SplitLoader`, `ImageStore`) que son testeables en aislamiento. Se descarta el diseño "max flex" (Protocols por todo) — overengineered para 4 datasets locales.

```python
# Codigo/src/data/_split_loader.py — helper puro
from dataclasses import dataclass
from pathlib import Path
import json

@dataclass(frozen=True)
class SplitLoader:
    path: Path

    def get(self, split: str) -> list[str]:
        data = json.loads(self.path.read_text(encoding="utf-8"))
        if split not in data:
            raise KeyError(f"split '{split}' no existe en {self.path}")
        return list(data[split])

    def all_ids(self) -> dict[str, list[str]]:
        return json.loads(self.path.read_text(encoding="utf-8"))
```

```python
# Codigo/src/data/_image_store.py
from dataclasses import dataclass
from pathlib import Path
from PIL import Image
import time

@dataclass(frozen=True)
class ImageStore:
    roots: tuple[Path, ...]          # múltiples directorios candidatos
    retries: int = 5
    backoff: float = 0.5             # segundos, exponencial

    def open(self, image_id: str, ext: str = ".jpg") -> Image.Image:
        for r in self.roots:
            candidate = r / f"{image_id}{ext}"
            if not candidate.exists():
                continue
            return self._open_with_retry(candidate)
        raise FileNotFoundError(f"imagen '{image_id}' no encontrada en {self.roots}")

    def _open_with_retry(self, path: Path) -> Image.Image:
        last: OSError | None = None
        for i in range(self.retries):
            try:
                return Image.open(path).convert("RGB")
            except OSError as e:
                last = e
                time.sleep(self.backoff * (2 ** i))
        raise last
```

`BaseDataset` queda como un wrapper fino:

```python
class BaseDataset(Dataset):
    def __init__(self, ids: list[str], store: ImageStore, transform, label_for):
        self.ids = ids
        self.store = store
        self.transform = transform
        self.label_for = label_for  # callable id → int

    def __len__(self) -> int: return len(self.ids)
    def __getitem__(self, i):
        img = self.transform(self.store.open(self.ids[i]))
        return {"image": img, "label": self.label_for(self.ids[i]), "metadata": {}}

    def class_weights(self) -> "torch.Tensor":
        from collections import Counter
        c = Counter(self.label_for(i) for i in self.ids)
        return torch.tensor([1.0 / c[k] for k in sorted(c)])
```

### Complejidad que oculta

- Parseo del JSON de splits.
- Política de retry NFS con backoff exponencial.
- Resolución multi-root del path (algunos datasets se montan en `data/raw/` y otros en `data/processed/`).
- Selección de `transform_preset` según `task`.
- Cálculo de class weights opcional.
- Versionado de splits.

## Estrategia de dependencias

**Categoría 2 — Local-substitutable.** Las dependencias son sólo filesystem (JSON + JPEGs). Los tests inyectan `tmp_path` directamente; no se necesita ningún port/adapter pattern.

## Estrategia de testing

**Nuevos tests** (todos contra `tmp_path`):

- `SplitLoader.get` filtra correctamente; `KeyError` con mensaje útil cuando el split no existe.
- `ImageStore.open` busca en múltiples roots, falla con `FileNotFoundError` si ninguno tiene la imagen.
- `ImageStore._open_with_retry` reintenta y eventualmente tira la última `OSError`.
- `load_dataset("ham10000", "train")` devuelve un `Dataset` de longitud igual a `SplitLoader.get("train")`.
- `load_dataset(..., return_weights=True)` devuelve weights que suman a 1 en cada clase observada.
- Versionado: `splits_version="v2"` apunta a `splits/ham10000_v2.json`.

**Tests viejos a borrar:** ninguno.

**Necesidades de entorno:** `pytest`, `Pillow`, `tmp_path`. Sin GPU, sin red.

## Recomendaciones de implementación

Lo que `src/data/` debe **poseer**:

- Política de retries / backoff para NFS.
- Resolución multi-root de paths.
- Versionado de splits.
- Cálculo de class weights.
- Mapeo `name → (clase de dataset, root, default_task)`.

Lo que debe **ocultar**:

- Detalles de qué directorios candidatos existen por dataset.
- Decisión de `transform_preset` según task.
- Construcción interna del `BaseDataset`.

Lo que debe **exponer**:

- `load_dataset(name, split, ...)` como entry-point.
- `SplitLoader` e `ImageStore` como helpers reusables (no son la API pública principal pero quedan importables).
- Las clases de dataset siguen siendo importables para escape-hatches.

**Migración recomendada:**

1. Crear `_split_loader.py` y `_image_store.py` con tests.
2. Refactorizar `BaseDataset` para recibir `ImageStore` y `SplitLoader` (en lugar de loadear in-line). Mantener backwards compat con un `from_paths(...)` constructor durante una iteración.
3. Mover la lógica de splits/retry fuera de cada dataset hijo. Cada `HAM10000Dataset.__init__` queda en ≈10 líneas.
4. Crear `load_dataset(name, split, ...)` como entrada canónica.
5. Documentar el versionado de splits en `docs/USAGE.md`.

**Líneas estimadas ahorradas:** ≈ 80-100 líneas netas, pero el beneficio principal es **testabilidad** del retry NFS y del versionado de splits.
